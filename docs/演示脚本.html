他会问什么（背这十一个）

追问怎么答
为什么不用 React / Vue？ 单页、状态不大、零构建。双击就能跑，面试现场少一个 npm 依赖就少一个故障点。换框架要 node_modules 加构建步骤，收益只有开发体验，这里不值。
为什么用 SSE 不用 WebSocket？ 只有服务端单向推送，浏览器原生 EventSource 就够，断线自动重连，走 HTTP 不用额外协议和握手。双向需求才轮到 WebSocket。
流式前端怎么处理？ 按 node 消息增量渲染：日志进队列逐条播、证据逐条 append、报告按块插入。用队列而不是直接刷，是为了保证每条都看得清——否则一次推 30 条等于没推。
为什么不用大模型直接 Text2SQL？ 演示场景不可控：同一句问法两次生成不同 SQL，还会编不存在的列。规则解析慢一点但确定、可解释、能单测。LLM 通道留着，复杂问法该用它，这是产品分层不是技术洁癖。
那这算 AI 产品吗？ 算，但 AI 不该背锅在"生成 SQL"这一步。它该放在理解问句、拆解归因路径、组织结论。取数必须确定，结论可以生成——这条线我划得很清楚。
数据量大了怎么办？ 现在 SQLite 单机，百万行以下够用（当前最大表 17 万行，单次聚合百毫秒级）。再往上换列存，DuckDB 或 ClickHouse，加预聚合层。这块没做，是明确边界。
怎么防 SQL 注入 / 误删？ 连接层 query_only 只读；所有值参数绑定不拼字符串；语句白名单只放 SELECT，加行数上限和超时。删表在引擎层就删不动。
归因的科学依据？ 加法分解：成员变化 = 本期 − 上期，占比 = 该成员变化 ÷ 全部成员变化绝对值之和。它回答"变化从哪来"，不回答"为什么变"。要因果得上实验或外部数据，报告里也写了这个边界。
为什么有两套分析路径？ 有领域模型时，毛利、ROI、库存周转这类指标要跨三张事实表算，用专用工具更准也更快；没有模型时走通用引擎，只做单表聚合，但换任何 CSV 都能用。优先级是：激活了上传数据就走通用，否则走内置。这是刻意分层，不是代码没统一。
左栏"分层记忆"是怎么分层的？ 两层：用户偏好（跨轮生效，比如默认看华东）和会话轮次（本次提问历史）。后端是进程内字典，Redis 接口留了没接。别把它说成向量记忆，它不是。
多轮 / 上下文记忆？ 有 memory 模块，进程内存储，Redis 没接。追问"那 8 月呢"能接上，服务重启会丢。这是待办，不是已完成。

工程落地：对接 ERP、上下游打通这 16 问

demo 的三块天然短板就是数据怎么进来、结论怎么出去、真上生产死在哪。这三块主动讲清楚，比被问穿强得多。每条按「现在是什么 → 真做要怎么做 → 现在缺什么」答，别把没做的说成做了。

一、上游：数据怎么接进来

追问怎么答
只会拖 Excel？我要接 ERP 怎么办？ 拖文件只是采集层的一个适配器。同一层还有三种：只读账号直连库（走视图，不给表权限）、定时抽数（DataX / Kettle，按 dt 增量）、变更捕获（MySQL binlog → Kafka）。抽完统一落 ODS，再进我这套语义层。ERP 真正的坑不在连接，在主数据：物料、客户、门店编码各系统不一致，得先有一张映射表，否则"同一个客户"在三个系统里是三个人。
增量怎么拉？断了怎么补？ 每条接入任务存一个水位线（最大 update_time 或自增 id），每次从水位线往后拉；任务失败不推水位线，重跑靠主键 upsert 保证幂等。我这边的等价物是数据集版本：每次上传是一个新表 + 一份元数据快照，失败不会污染旧表。真增量没做，现在是全量替换——17 万行替换只要一两秒，上千万行就不行了。
上游数据脏怎么办？ 三档校验，按代价排序：硬规则（主键唯一、金额非负、日期不越界）直接拦；软规则（空值率突增、枚举越界、日环比超 3 倍）进隔离区等人看；对账（上游笔数/金额 vs 入库笔数/金额）出日报。脏数据不进主表，先进 quarantine 表——这点比"报错中断"重要，分析系统最怕的是悄悄少了一部分数据。
迟到数据 / 重复数据？ 迟到：按 dt 分区，允许回刷过去 N 天，重跑覆盖同一分区，天然幂等。重复：业务主键 + 更新时间取最新一条，我用的是"上传即新表 + 元数据指向"，没有原地更新，所以不存在半更新状态。缺失的一环是没有调度，现在靠人拖文件。
财务和业务两套销售额，口径不一致怎么办？ 这就是我为什么要做语义层：指标不是 SQL 字符串，是"指标 key + 口径 SQL + 版本 + 负责人"。内置模型里 METRICS 是白名单，改口径要改代码、要评审、要留版本号。业务口径（含税/退货）和财务口径（不含税/账期）可以并存，但必须各自有名字，最怕的是同一个名字两套算法。这块 demo 只有 5 个指标，没有版本管理。

二、下游：结论怎么打通回去

追问怎么答
分析结果怎么回到业务系统？ 三条出口：API（结论对象已经是结构化 JSON，前端只是渲染器之一）、推送（企微/钉钉 webhook，异常波动主动推，不等业务来问）、导出（Excel/PDF 进汇报流程）。要回写到 ERP 或工单系统就是另一回事了：写通道必须单独开、走审批、留回滚，绝不能和只读的分析库共用账号。
怎么保证它不写坏生产库？ 三层，层层独立：连接层 PRAGMA query_only（SQLite 的只读模式，写语句在引擎层就报错）；语句层只放行 SELECT，加超时 8 秒和行数上限 5000；参数层全部绑定，不拼字符串。再接生产库的话再加两条：用只读从库、EXPLAIN 预检全表扫直接拒绝。
权限怎么做？谁能看哪张表、哪一行？ 现在没有，这是真缺口——本地单用户，默认你什么都能看。设计上是三层：数据集级 RBAC（谁能激活哪张表）、行级过滤（生成的 SQL 强制注入 WHERE org_id = ?，值来自登录态不来自问句）、列级脱敏（手机号/身份证按角色打码）。行级过滤必须做在SQL 生成层而不是前端，否则谁都能绕。
那和帆软 / PowerBI / Superset 什么关系？ 不是替代，是入口层。它们解决"看板怎么看"，我解决"问题怎么问"。语义层和权限层是共用的，理想形态是我产出结论和图表 spec，直接喂给现有看板；反过来说，如果公司已经有成熟 BI，我这套的定位是给不会用 BI 的人开一个自然语言口子，而不是重做一遍报表。
多人同时用呢？ 现在单进程 uvicorn + SQLite，读并发没问题（WAL），写有锁。生产换 PostgreSQL + 连接池，分析请求进队列限流，长查询降级成异步任务。真正的瓶颈不是数据库，是大模型的并发和限流——同一时刻几十个人提问，token 成本会先炸。

三、生产化：技术上的硬边界

追问怎么答
数据量到 TB 呢？ SQLite 单机在千万行以下够用，现在最大表 17 万行、聚合百毫秒级。往上走三步：换列存（DuckDB 单机 / ClickHouse 集群）、建预聚合宽表（按天×渠道×区域的物化视图，把 90% 的查询打在汇总层）、查询下推 + 结果缓存（同一问句 + 同一份数据版本 → 直接返回）。这三步按代价从小到大做，多数公司卡在第二步没做，直接上集群反而更慢。
能实时吗？ 现在是 T+1 批处理，因为绝大多数经营分析就是看昨天的数。实时成本差一个数量级：CDC + 流计算 + 实时 OLAP，运维复杂度完全不同。真要实时，也是只对少数几个指标（大促当天的 GMV、支付成功率）做实时链路，其余走 T+1，而不是全量上流。
怎么证明它答得准？准确率多少？ 靠黄金集回归：100 条真实问句 + 标准 SQL + 标准答案，每次改规则跑一遍，看三个指标——意图准确率、SQL 执行成功率、数值一致率。现在手工核对了 8 个问题（表格里那些数字都是我拿 pandas 对过的），没有自动化回归，这是我要补的第一件事。
大模型幻觉怎么控？ 把"生成"和"计算"切开：数字只能来自 SQL 结果，模型不许算数；规划层输出的是结构化 plan（Pydantic 强类型），不是自由 SQL，字段名必须能在画像里找到，否则拒绝；报告里的每个数字都挂 evidence id，点开能看到那条 SQL。自检那 6 项就是在拦"数字对不上"——比如拆解项之和必须等于总量，不通过就退回重查。
成本呢？一次提问多少钱？ 默认模型是关的，走本地规则引擎，零 token 成本，单次分析 80 毫秒左右。开 qwen-plus 的话一次大概几千 token，按量算是分钱级，但人多就得上缓存和限流。这也是我为什么坚持"规则打底、模型增强"——不是技术洁癖，是成本结构决定的。
线上出问题怎么排查？ 现在有的：每个节点的真实耗时、每步的 trace、每条 SQL 的参数/行数/扫描计划、审计日志（谁在什么时候问了什么）。缺的是指标化和告警——没有 Prometheus 打点、没有链路追踪、没有错误率看板。现在是"能事后查"，还不是"能事前发现"。
怎么交付部署？ 现在是双击 bat 起 pythonw，监听 127.0.0.1，不装任何东西。这是刻意的：面试现场最怕环境问题。真要交付就 Docker Compose 三个容器（web / db / 调度），反向代理加鉴权，内网离线包。我们客户有内网环境的话，模型也得走本地部署，不能用公有云 API。
如果重做一遍，你先改什么？ 三件事，按顺序：一、自动化回归（黄金集，不然每次改规则都是赌博）；二、语义层独立出来（现在指标定义和 SQL 生成耦在一个文件里）；三、把 LLM 通道真正接上并做成可降级（现在是规则单跑，复杂问法直接退化）。功能上不缺，缺的是"改得动、测得准"。
这一段的说话方式：被问到没做的，先给一句"这个没做"，再给设计，最后给"为什么现在不做"。三句话说完就停。最忌讳的是把设计讲得比实现还详细——面试官一追问细节就露馅。
